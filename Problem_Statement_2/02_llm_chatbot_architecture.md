## 1. High-Level Architectural Approach

A production-grade LLM chatbot is an orchestrated distributed platform designed to deliver **low latency**, **contextual groundedness**, and **Zero Trust security**. Rather than making unconstrained calls to an API, the system separates client transport, conversation memory, knowledge retrieval, and model inference into 6 decoupled architectural layers.

## 2. In-Depth Breakdown of Core Components

### 1. API Gateway & Session Memory Layer
* **Transport Protocol:** Streaming responses require low Time-To-First-Token (TTFT). Server-Sent Events (SSE) or WebSockets allow tokens to stream back as they are generated by the model.
* **Conversation State & Memory:** Raw multi-turn history quickly exhausts the model's context window and inflates costs. Production architectures use:
  * **Sliding Window Buffer:** Retaining only the last $K$ conversational turns (e.g., $K=6$).
  * **Summary Memory Buffer:** As dialogue deepens, older turns are asynchronously summarized by a compact model and injected as background context.

### 2. Guardrails & Zero-Trust Safety Layer
* **Prompt Injection Defense:** Filters adversarial inputs designed to bypass system instructions.
* **PII Redaction:** Strips sensitive data (API keys, IP addresses, PII) before payloads hit vector databases or third-party inference APIs.

### 3. RAG Retrieval Subsystem
* **Semantic Chunking:** Documents are split into 256–512 token chunks with 10% overlap to preserve semantic continuity across paragraph boundaries.
* **Hybrid Search (Dense + Sparse):** Dense embeddings capture conceptual meaning, while BM25 keyword search captures exact names, ports, and error codes. Results are merged via **Reciprocal Rank Fusion (RRF)**.
* **Cross-Encoder Re-Ranking:** The top 20 retrieved candidates pass through a cross-encoder model (e.g., BAAI/bge-reranker) to score true document-query relevance. Only the top 3 highest-scoring chunks are injected into the final prompt, drastically minimizing hallucinations.

### 4. Prompt Assembly & Orchestration Layer
* Combines the system prompt, conversational memory summary, and retrieved chunks into a templated prompt.
* Uses system directives such as:  
  > *"If the query cannot be strictly validated using the retrieved context, acknowledge the limitation rather than synthesizing an unverified answer."*

### 5. LLM Inference Engine
* Serves open-weights (e.g., LLaMA-2-13B, Mistral-7B) using high-throughput serving engines like **vLLM** (PagedAttention) or cloud endpoints.
* Configures sampling parameters based on use case: `temperature=0.2` for factual enterprise tasks, higher for creative responses.

### 6. Observability, Telemetry & Evaluation
* **Distributed Tracing:** Implements OpenTelemetry or LangSmith to trace the latency of every step (retrieval time, rerank time, TTFT).
* **Evaluation via the RAG Triad:**
  1. **Context Relevance:** Does the retrieved context address the prompt?
  2. **Groundedness:** Is the generated answer backed by the context?
  3. **Answer Relevance:** Does the answer directly solve the user's intent?
